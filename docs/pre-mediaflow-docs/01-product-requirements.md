# MediaFlow 产品需求文档

> 文档编号：MF-PRD-001  
> 版本：1.2  
> 状态：可进入 MVP 开发

## 1. 背景

下载工具、PT、网盘或人工复制得到的影视文件通常带有发布组、分辨率、编码、音轨和语言标签。例如：

```text
[DBD-Raws][Dragon Ball][001][1080P][BDRip][HEVC-10bit][FLACx2].mkv
[DBD-Raws][Dragon Ball][001][1080P][BDRip][HEVC-10bit][FLACx2].sc.ass
[DBD-Raws][Dragon Ball][001][1080P][BDRip][HEVC-10bit][FLACx2].tc.ass
```

此类命名不一定能被 Emby 稳定识别，也可能导致字幕无法自动挂载。MediaFlow 需要将其安全转换为：

```text
龙珠 S01E01.mkv
龙珠 S01E01.sc.ass
龙珠 S01E01.tc.ass
```

并分类进入媒体库，再通知 Emby 更新。

## 2. 产品目标

### 2.1 核心目标

- 自动发现新增媒体文件并确认文件写入完成。
- 从文件和目录名称中提取标题、年份、季、集、绝对集、特别篇和技术标签。
- 搜索并匹配 TMDB/Bangumi 条目。
- 支持人工确认条目和季集映射。
- 同步处理视频、字幕、NFO、图片和其他附属文件。
- 按模板生成适合 Emby 的目录和文件名。
- 支持移动、复制、硬链接和符号链接。
- 所有变更先预览，默认不覆盖，关键操作可回滚。
- 文件成功入库后调用 Emby API 更新媒体库。

### 2.2 非目标

MVP 不实现：

- BT/PT 下载控制；
- 视频转码、压制、重封装；
- 字幕自动校轴；
- 在线播放；
- 替代 Emby、Sonarr 或 Radarr；
- 自动删除无法识别文件；
- 修改 Emby 客户端界面。

## 3. 用户角色

### 3.1 管理员

拥有全部配置和文件操作权限，可配置目录、媒体库、命名规则、外部服务并执行或回滚任务。

### 3.2 只读用户

MVP 不实现。后续仅查看任务、日志和媒体库状态。

## 4. 核心术语

| 术语 | 定义 |
|---|---|
| 待整理目录 | 下载器或用户放入原始媒体文件的目录 |
| 媒体库目录 | Emby 已配置或准备配置的电影、电视剧、动画目录 |
| 媒体任务 | 对一组关联视频、字幕及附属文件进行识别和处理的业务任务 |
| 操作计划 | 实际修改文件前生成的源路径到目标路径映射及操作类型 |
| 条目绑定 | 将源目录与已确认的 TMDB/Bangumi 条目长期关联 |
| 绝对集数 | 动画发布组使用的连续集号，如 001、153 |
| 季集编号 | Emby 常用的 `S01E01` 编号 |

## 5. 典型流程

### 5.1 动画导入

1. 用户将《龙珠》文件夹放入 `/inbox/anime`。
2. 系统等待文件稳定。
3. 解析器提取标题 `Dragon Ball`、绝对集 `001`、字幕语言 `sc/tc`。
4. 系统搜索 Bangumi 和 TMDB。
5. 用户确认条目“龙珠”，并设定绝对集 1 对应 `S01E01`。
6. 系统展示完整操作预览。
7. 用户确认后，系统执行重命名和分类。
8. 系统记录操作并触发 Emby 刷新。

### 5.2 PT 保种

1. 用户选择操作模式“硬链接”。
2. 系统验证源目录和目标目录位于同一文件系统。
3. 创建目标硬链接，不修改源文件。
4. 字幕文件按配置执行复制或硬链接。
5. Emby 扫描目标媒体库。

### 5.3 条目歧义

1. 文件夹名为 `Monster`。
2. 搜索结果包含多个候选。
3. 第一名得分未达到阈值或领先差不足。
4. 任务进入 `WAITING_CONFIRMATION`。
5. 用户选择正确条目后才能生成操作计划。

## 6. 功能需求

### 6.1 目录与扫描

| 编号 | 需求 |
|---|---|
| FR-SCAN-001 | 管理员可以新增、编辑、启用和禁用待整理目录。 |
| FR-SCAN-002 | 每个待整理目录可指定媒体类型：电影、电视剧、动画或自动判断。 |
| FR-SCAN-003 | 支持手动扫描、定时扫描、文件系统事件和外部 Webhook。 |
| FR-SCAN-004 | 扫描支持递归和非递归模式。 |
| FR-SCAN-005 | 系统必须忽略临时下载文件、隐藏文件和用户自定义规则。 |
| FR-SCAN-006 | 文件大小和修改时间在稳定窗口内无变化后才可处理。 |
| FR-SCAN-007 | 同一路径的重复扫描不得创建重复执行任务。 |
| FR-SCAN-008 | 网络挂载事件不可靠时，定时扫描作为兜底。 |

### 6.2 文件解析

| 编号 | 需求 |
|---|---|
| FR-PARSE-001 | 支持 `S01E01`、`1x01`、`E01`、`[001]`、`EP01` 等格式。 |
| FR-PARSE-002 | 支持多集文件，如 `S01E01-E02`。 |
| FR-PARSE-003 | 支持 `SP01`、`OVA01`、`OAD01` 等特别篇标记。 |
| FR-PARSE-004 | 提取发布组、年份、分辨率、来源、编码、位深和版本。 |
| FR-PARSE-005 | 从字幕文件名中提取语言和字幕属性。 |
| FR-PARSE-006 | 用户可创建带优先级、目录范围和发布组范围的自定义正则规则。 |
| FR-PARSE-007 | 规则管理页必须提供无副作用的在线测试。 |
| FR-PARSE-008 | 解析失败不得触发文件操作。 |

### 6.3 元数据匹配

| 编号 | 需求 |
|---|---|
| FR-META-001 | 电影和电视剧可搜索 TMDB。 |
| FR-META-002 | 动画可优先搜索 Bangumi，并以 TMDB 为补充。 |
| FR-META-003 | 所有适配器输出统一候选模型。 |
| FR-META-004 | 匹配评分至少考虑标题、别名、年份、媒体类型和集数。 |
| FR-META-005 | 自动匹配需同时满足最低得分和第一名领先差。 |
| FR-META-006 | 中低置信度结果必须由用户确认。 |
| FR-META-007 | 用户确认后可保存目录绑定。 |
| FR-META-008 | API 失败时应使用有效缓存或进入可重试状态。 |
| FR-META-009 | 外部服务返回结构不得直接作为核心领域模型存储。 |

### 6.4 季集映射

| 编号 | 需求 |
|---|---|
| FR-EP-001 | 标准季集编号直接映射。 |
| FR-EP-002 | 绝对集数可按区间映射为季集编号。 |
| FR-EP-003 | 用户可对文件列表按自然排序批量指定起始季和起始集。 |
| FR-EP-004 | 特别篇默认使用 Season 00，但必须允许显式覆盖。 |
| FR-EP-005 | 多个特别篇来源不得自动映射到相同目标集号。 |
| FR-EP-006 | 映射结果需要做目标编号唯一性校验。 |

### 6.5 字幕管理

| 编号 | 需求 |
|---|---|
| FR-SUB-001 | 支持 ASS、SSA、SRT、VTT、SUB/IDX 和 SUP。 |
| FR-SUB-002 | 根据基础文件名、季集编号、发布组和目录计算视频字幕关联分数。 |
| FR-SUB-003 | 字幕语言可标准化为短标签或 BCP 47 标签。 |
| FR-SUB-004 | 同一剧集的字幕必须跟随视频目标基础名。 |
| FR-SUB-005 | 无法唯一关联的字幕进入人工确认。 |
| FR-SUB-006 | 检测孤立字幕、重复字幕、空文件和无法解析文件。 |
| FR-SUB-007 | MVP 只读取内封字幕信息，不自动抽取或封装。 |

### 6.6 命名与分类

| 编号 | 需求 |
|---|---|
| FR-NAME-001 | 动画和电视剧默认模板为 `{title} S{season:02}E{episode:02}`。 |
| FR-NAME-002 | 电影默认模板为 `{title} ({year})`。 |
| FR-NAME-003 | 文件夹和文件名模板可按媒体库配置。 |
| FR-NAME-004 | 自动清理目标平台非法字符并保留扩展名。 |
| FR-NAME-005 | 支持标题语言优先级和用户手动标题。 |
| FR-NAME-006 | 完整路径长度超过配置时必须报错或按确定规则缩短。 |

### 6.7 文件操作

| 编号 | 需求 |
|---|---|
| FR-FILE-001 | 支持移动、复制、硬链接和符号链接。 |
| FR-FILE-002 | 执行前必须生成可审阅的操作计划。 |
| FR-FILE-003 | 默认冲突策略为询问，不得覆盖。 |
| FR-FILE-004 | 跨文件系统移动必须按“复制、校验、删除源”执行。 |
| FR-FILE-005 | 硬链接前必须确认同一设备。 |
| FR-FILE-006 | 每个文件操作必须写入操作记录。 |
| FR-FILE-007 | 用户可回滚尚未被外部修改的成功操作。 |
| FR-FILE-008 | 部分失败时必须保留可恢复信息，不得静默删除源文件。 |
| FR-FILE-009 | 同一个操作计划重复提交不得重复创建目标文件。 |

### 6.8 任务管理

| 编号 | 需求 |
|---|---|
| FR-TASK-001 | 任务状态必须持久化。 |
| FR-TASK-002 | 页面可查看任务状态、步骤、错误、候选、操作计划和日志。 |
| FR-TASK-003 | 支持确认、重试、取消、重新分析和回滚。 |
| FR-TASK-004 | 同一源文件不得被多个执行任务并发处理。 |
| FR-TASK-005 | 服务重启后恢复未完成任务或标记为需要人工处理。 |
| FR-TASK-006 | 文件成功但 Emby 失败时只重试 Emby，不重复文件操作。 |

### 6.9 Emby 集成

| 编号 | 需求 |
|---|---|
| FR-EMBY-001 | 管理员可配置服务器地址和静态 API Key。 |
| FR-EMBY-002 | 可测试连接并读取服务器及媒体库信息。 |
| FR-EMBY-003 | 文件处理完成后可调用全库扫描或路径更新接口。 |
| FR-EMBY-004 | 短时间内的刷新请求需要合并。 |
| FR-EMBY-005 | 刷新失败采用退避重试。 |
| FR-EMBY-006 | Emby 不可用不回滚已完成的文件操作。 |

### 6.10 Web 管理界面

| 编号 | 需求 |
|---|---|
| FR-UI-001 | 提供登录、仪表盘、任务列表、任务详情和待确认页。 |
| FR-UI-002 | 提供监听目录、媒体库、规则、元数据源、Emby 和系统设置页。 |
| FR-UI-003 | 所有破坏性操作必须二次确认。 |
| FR-UI-004 | 操作预览突出显示冲突、未知映射和将被删除的源文件。 |
| FR-UI-005 | 长时间任务由轮询或事件流更新状态，不阻塞 HTTP 请求。 |

## 7. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-SAFE-001 | 默认配置下不得覆盖任何现有目标文件。 |
| NFR-SAFE-002 | 删除源文件只能发生在跨设备移动复制校验成功之后。 |
| NFR-PERF-001 | 扫描 10,000 个文件时采用分页/流式处理，避免一次性加载。 |
| NFR-PERF-002 | 普通文件名解析不访问网络，单文件平均目标低于 10 ms。 |
| NFR-REL-001 | 单一外部 API 失败不得导致进程退出。 |
| NFR-REL-002 | 执行器必须保证操作记录和文件状态可对账。 |
| NFR-COMP-001 | 支持 Linux x86-64、ARM64 和主流 NAS Docker 环境。 |
| NFR-SEC-001 | 所有输入路径必须限制在授权挂载根目录内。 |
| NFR-SEC-002 | 密钥不得写入日志、前端状态或导出配置。 |
| NFR-OBS-001 | 每个请求、任务和文件操作具有可关联 ID。 |
| NFR-TEST-001 | 文件操作、状态机、解析器和回滚核心路径必须有自动化测试。 |

## 8. MVP 范围

### 8.1 必须交付

- Docker Compose 部署；
- 单管理员登录；
- 监听目录与媒体库配置；
- 手动扫描；
- 文件稳定性检查；
- 视频、字幕识别与分组；
- 标准季集和方括号绝对集解析；
- 自定义正则；
- TMDB/Bangumi 搜索与人工确认；
- 手动绝对集映射；
- 操作计划预览；
- 移动、复制、硬链接；
- 视频字幕同步命名；
- 冲突保护；
- 操作记录与回滚；
- Emby 连接测试和刷新；
- 任务列表、详情和设置页面。

### 8.2 延后交付

- 自动下载字幕；
- NFO 完整生成；
- Plex/Jellyfin；
- 自动复杂分季；
- 多用户权限；
- 分布式 worker；
- 移动端应用；
- 下载器双向控制。

## 9. 产品验收门槛

MVP 上线前必须满足：

1. 龙珠示例的三个文件可以正确同步重命名；
2. 目标已存在时源和目标均保持不变；
3. 文件操作失败可定位到具体文件和错误码；
4. 成功任务可回滚；
5. 服务在执行中崩溃后不会盲目重复复制；
6. Emby 离线时文件处理仍保持成功结果；
7. 所有测试使用临时目录，不接触真实媒体库；
8. Docker 以非 root 身份运行并通过挂载权限测试。
