# AutoBangumi 能力整合计划

> 基线：AutoBangumi 官方文档、`E:\MyData\003.CodeSpace\Auto_Bangumi` 的 `fd798519` 源码及 [完整源码调研](autobangumi-project-analysis.md)。本文件是 CyMediaFlow 的实施范围与验收标准，不复制 AutoBangumi 的数据库、API 或页面。

## 产品定位与页面

AutoBangumi 能力负责 RSS／资源搜索、发布名解析、追番规则、下载与初步整理；CyMediaFlow 现有的作品匹配、季集映射、NFO、图片、字幕与媒体库展示继续承接下载结果。播放器功能不纳入。

左侧导航增加“AutoBangumi”，其页面下设“追番规则、RSS、资源搜索、下载任务、日历、活动记录”子标签。沿用简洁圆角设计，不在首页放置自动追番工作台。现有设置页分为“CyMediaFlow”与“自动追番”两组；Bangumi、TMDB 与代理配置复用，下载器凭据只写入、不回传。

## 用户选择：范围 A

按以下顺序形成第一条可运行链路：

1. 增加独立页面、子标签、设置分区和持久化模型。默认关闭自动下载，以免旧 NAS 数据在升级时被直接处理。
2. 实现 qBittorrent 连接测试与 RSS 管理。RSS 支持标准 RSS／Atom，限制响应大小与超时。
3. 用 CyMediaFlow 的发布名解析器产出可见候选；追番规则管理作品名称、别名、季号、字幕组、分辨率、过滤词和保存目录。解析不确定或冲突时停在待审核。
4. 定时与手动拉取 RSS，按源和规范化发布标识去重；只有命中启用规则且通过过滤时添加 qBittorrent。持久化每次决策和下载任务。
5. 跟踪下载状态，完成后按 `{标题}/Season N/{标题} SxxExx.ext` 生成整理计划。重命名经下载器 API 执行并记录状态；已有目标、复杂合集及不明文件先待审核。
6. 整理成功后刷新 CyMediaFlow 媒体索引，并在活动记录写明关联的作品或待手动匹配的原因。

“下载完成 → NFO/图片自动生成 → Emby 精准刷新”的深度接力是下一阶段：需要先核实作品元数据绑定、字段锁和 Emby API 权限。范围 A 的验收点是“发现一集 → 下载 → 安全整理 → 首页可看到”。

## 技术安排

- 新增 `domain/automation`、`application/automation`、`infrastructure/automation` 与 `/api/v1/automation`。与现有 SQLAlchemy 会话和 FastAPI 生命周期共用配置及数据库。
- 新表保存 RSS 源、追番规则、发布候选、下载任务、文件操作和活动记录；任务有稳定唯一键及状态。配置更改后下次调度生效。
- 解析、规则准入、下载计划、执行与整理分层。qBittorrent 以独立适配器承载登录、添加、查询与文件改名；文件路径同时按下载器视角和 CyMediaFlow 容器视角校验。
- 调度器一次只运行一轮，避免同一源与下载任务并发重复处理。启动时先对账未完成任务；网络失败按源记录，其他源继续。
- 外部请求使用超时、大小上限；下载器密码只读写存储、不通过 GET 回传。真实 NAS 文件不用于自动化测试，使用临时媒体目录与模拟 RSS／下载器完成回归。

## 范围 A 已实现与使用顺序（2026-10-10）

当前实现包括左侧 AutoBangumi 入口（页面内为追番规则、RSS、发布候选、下载任务、活动记录五个子标签）、设置页单独的自动追番分区、RSS/Atom 源管理、发布解析预览、规则过滤、qBittorrent 连接与任务提交、下载状态同步、下载器 API 内的媒体/字幕改名及媒体库重新扫描。所有配置与任务状态写入应用原有 SQLite 数据库；新安装及旧库升级后自动下载均为关闭状态。

在 NAS 上首次使用时，先确保 qBittorrent Web API 可从 **CyMediaFlow 后端容器** 访问；在“设置 → 自动追番”中填写其 HTTP 地址、用户名、密码和“下载器视角的保存根目录”。例如 qBittorrent 将 `/downloads/Bangumi` 挂载到某个 NAS 目录，而 CyMediaFlow 将同一份目录挂载为 `/media`，则下载根目录填 `/downloads/Bangumi`，原有“媒体目录”填 `/media`。这两个路径不是同一个字符串，但必须指向同一份实体文件。RSS 需要代理时才填写独立的 RSS 代理；它不会沿用 Bangumi 代理。先保存，再测试下载器，确认连接后仍不要急于启用自动追番。

随后在“RSS”添加订阅源，点击“预览”检查标题能否识别；在“追番规则”创建作品标题、发布标题别名、本地季号、集数偏移及可选字幕组/分辨率/排除词。同一个聚合 RSS 可以关联多条追番规则。先在自动追番关闭状态下点“刷新”，到“发布候选”核对每条 `已匹配／已跳过／待审核` 的原因。确认后才在设置中启用，并再次刷新或等待定时检查。

匹配成功的发布按 `作品目录/Season N` 提交给 qBittorrent，任务使用稳定的 `cymf-<发布ID>` 标签去重。下载完成时，只有单视频、同层文件且目标无冲突的任务才自动整理为 `标题 SxxExx.ext`；同种子的字幕也按识别出的简体、繁体、英文标签改名。整理通过 qBittorrent `renameFile` 执行，不直接搬动做种中的文件；改名清单持久化，可在进程重启后继续核对。已有目标文件、合集、多视频、嵌套文件或未知映射会停在“待审核”，不会覆盖原文件。只有由本模块新添加的任务会进入此自动整理流程，既有媒体库不会被批量改名。

整理成功后刷新 CyMediaFlow 媒体扫描，作品可在首页出现；本阶段不自动生成 NFO/图片，也不调用 Emby 刷新 API。现有的作品匹配、季集映射、刮削信息与 NFO 功能仍在原有详情抽屉中手动配置。范围 A 也不含站点搜索、日历、缺集补全、V2/V3 替换、aria2 或播放器，这些属于后续优先级。

验收在临时媒体目录和模拟 RSS/qBittorrent 中完成，覆盖重复刷新只提交一次、目标冲突不覆盖、删后重加 RSS、下载器 Web API 请求、移动端页面与重启可查询的持久任务。真实 NAS qBittorrent、实际 RSS 和容器挂载映射仍需在部署后以一条测试订阅验证，**不要直接对大批现有资源启用规则**。
