# CyMediaFlow 开发日志

## 2026-08-22：MVP 功能确认、管理操作台方案与实施步骤

### 1. 背景与结论

CyMediaFlow 定位为运行在 NAS 上、位于下载目录与 Emby 媒体库之间的影视自动化管理工具，首期重点解决：

1. 下载资源命名不统一，导致 Emby 对作品、季和集的识别不稳定；
2. Bangumi/TMDB 可以检索到正确条目，但 Emby 无法稳定匹配或刮削。

基于现有规格和 NAS 媒体库只读分析，原方案需要补充两项 P0 能力：

- 现有媒体库的只读审计、问题分类和修复计划；
- 将 MediaFlow 已确认的作品身份传递给 Emby 的最小 NFO 生成及刷新后验证。

开发顺序确定为：先只读审计，再人工确认和修复，最后逐步开放自动化。第一版不得直接对真实媒体库执行无人值守改名。

### 2. 已确认的 MVP 功能

#### 2.1 目录与媒体库管理

- 配置下载/待整理目录和现有 Emby 媒体库目录；
- 支持动画剧集、动画电影、特别篇和附加内容；
- 检查目录可读写性、设备、文件系统、剩余空间和路径映射；
- 支持手动扫描和定时扫描，SMB/NFS 使用定时扫描兜底；
- 所有文件操作限制在显式授权根目录内。

#### 2.2 现有媒体库审计

审计阶段默认只读，检测：

- 不符合模板的作品目录、季目录和媒体文件；
- 缺少年份、季目录或季集编号；
- 同一 Bangumi/TMDB ID 对应多个顶层目录；
- 同一季集槽位存在多个视频；
- 孤立的 NFO、图片和字幕；
- 视频缺少同名分集 NFO；
- NFO 缺少标题、年份、季集号或外部 ID；
- 动画电影被识别成电视剧；
- `tvshow.nfo` 位置异常；
- SMB 短文件名、乱码、非法字符和超长路径；
- 目录名、文件名、NFO 与 Emby 条目之间的字段冲突。

审计问题按以下等级输出：

```text
INFO      无需处理
WARNING   建议整理
REVIEW    必须人工确认
CONFLICT  无法生成安全计划
CRITICAL  可能存在路径或文件安全问题
```

审计只输出证据和建议，不自动删除孤立文件或重复视频。

#### 2.3 文件名解析与分组

至少支持：

- `S01E01`、`1x01`、`E01`、`EP01`；
- `[001]`、`[001v2]`、`[001-002]`；
- `Title - 01`；
- `S01E01-E02`；
- `SP01`、`OVA01`、`OAD01`、`[00&SP]`；
- `NCOP`、`NCED`、`PV`、`CM`、`Menu`、`Making`、`Trailer`；
- 发布组、年份、分辨率、来源、编码、位深和版本；
- 简繁字幕、双语字幕和 forced/SDH 等字幕属性。

每次解析返回字段、置信度、警告和逐步 Trace。解析器不得访问网络或修改文件。

分组需要识别：

- 视频及其外挂字幕和 Sidecar；
- 同集不同版本；
- 多集文件；
- 特别篇和附加内容；
- 发布组整包目录；
- 已删除视频遗留的 Sidecar；
- 同内容不同扩展名或发布组版本。

#### 2.4 元数据搜索与身份绑定

- 动画优先 Bangumi，并行或回退查询 TMDB；
- 动画电影必须正确映射为 Movie；
- 按标题、别名、年份、媒体类型和集数评分；
- 展示候选和评分明细，中低置信度必须人工选择；
- 支持直接输入 Bangumi ID 或 TMDB ID；
- 保存目录到作品的长期绑定；
- 同时保存 Bangumi、TMDB、TVDB 等已知 ID；
- 外部服务不可用时使用缓存或本地条目；
- 已绑定目录不得因临时搜索失败自动切换作品。

#### 2.5 季集映射

- 标准季集直接映射；
- 支持动画绝对集和区间映射；
- 长篇动画的 `E421` 等编号必须结合目录绑定，不能直接解释为 `S01E421`；
- 特别篇通过显式规则映射到 Season 00；
- 附加内容单独分类，不能与正式剧集争用集号；
- 支持批量顺序映射和单项覆盖；
- 生成计划前检查目标季集冲突和映射完整性。

#### 2.6 命名与目录整理

默认模板：

```text
剧集目录：{title} ({series_year})/Season {season:02}
剧集文件：{title} S{season:02}E{episode:02}
电影目录：{title} ({year})
电影文件：{title} ({year})
字幕文件：{video_stem}.{language}.{flags}.{extension}
```

规则：

- 多季作品优先使用整个系列的首播年份；
- Provider 明确认定续作为独立作品时，才允许独立顶层目录；
- 多版本必须使用 edition、release group 或其他稳定后缀区分；
- 对 Windows、Linux、SMB 的非法字符、大小写和 Unicode 冲突进行预检；
- 清理名称时必须保留原始解析信息，执行阶段不得重新推断名称。

#### 2.7 最小 NFO 生成与修复

最小 NFO 从 P1 提升为 MVP，支持：

- `tvshow.nfo`；
- `season.nfo`；
- `movie.nfo`；
- 与视频同名的分集 NFO。

MVP 至少写入：

- 标题和原始标题；
- 年份；
- 内容类型；
- 季号和集号；
- Bangumi/TMDB/TVDB ID；
- 系列、季和分集的关联身份。

已有 NFO 默认不覆盖：无变化时跳过；可补充内容时展示 Diff；存在字段冲突时进入人工确认；完整替换必须显式授权并保留可恢复信息。

#### 2.8 文件操作与回滚

- MVP 支持 move、copy、hardlink，symlink 放到 P1；
- 所有操作先生成不可变操作计划；
- 默认不覆盖任何目标文件；
- 执行前重新检查源快照、目标冲突、空间和设备；
- 视频、字幕、NFO 和图片同步处理；
- 每个文件变化都写入持久化操作记录；
- 支持安全回滚；
- 状态不确定时进入恢复流程，不盲目重试；
- 孤立 NFO、图片和疑似重复视频默认只报告，不自动删除。

#### 2.9 Emby 集成与验证

- 测试 Emby 连接并读取媒体库和物理路径；
- 通知媒体新增/更新，支持全库或指定项目刷新；
- 刷新请求合并、退避重试；
- 文件成功而 Emby 失败时只重试 Emby；
- 刷新后验证 Path、Item 类型、ProviderIds、季号、集号和重复条目；
- Emby 返回刷新成功不等于元数据验证成功。

最终成功条件：

```text
文件处理成功
AND Emby 已发现目标路径
AND 作品身份一致
AND 季集信息一致
```

建议增加状态：

```text
FILES_COMPLETED
EMBY_DISCOVERED
EMBY_METADATA_VERIFIED
EMBY_METADATA_MISMATCH
SUCCESS
```

#### 2.10 MVP 非目标

- 下载器和 PT 站点管理；
- 视频转码、压制和重封装；
- 字幕下载、翻译、OCR 和校轴；
- 自动删除重复视频；
- Plex/Jellyfin；
- 多用户权限和移动端应用；
- 默认开启无人值守自动执行；
- 自动覆盖已有媒体文件或 NFO。

### 3. 管理操作台方案

#### 3.1 总体架构

```text
React 管理操作台
        │ REST + SSE
        ▼
FastAPI 模块化单体
        ├── 审计与解析
        ├── 元数据匹配
        ├── NFO 与命名计划
        ├── 文件执行与回滚
        ├── Emby 对账
        └── 持久化 Worker
                │
                ▼
          SQLite WAL
```

技术栈：

- 后端：Python 3.10+、FastAPI、SQLAlchemy 2、Alembic、Pydantic 2、HTTPX；
- 前端：React、TypeScript、Vite、React Router、TanStack Query；
- 数据库：SQLite WAL；
- 后台任务：数据库持久化队列；
- 媒体探测：FFprobe；
- 部署：Docker，支持 Linux amd64/arm64 NAS。

#### 3.2 前端页面

| 路由 | 页面 | 主要内容 |
|---|---|---|
| `/login` | 登录 | 单管理员认证、初始化密码修改 |
| `/` | 仪表盘 | 审计问题、待确认、冲突、Emby 状态、最近任务 |
| `/audit` | 媒体库审计 | 作品目录、命名、NFO、重复、风险等级 |
| `/audit/:id` | 审计详情 | 文件系统、NFO、Provider、Emby 三方对比 |
| `/tasks` | 全部任务 | 状态、来源、条目、目标、错误和进度 |
| `/tasks/pending` | 待确认工作台 | 候选、季集、重复、NFO 和路径冲突处理 |
| `/tasks/:id` | 任务详情 | 解析、元数据、映射、NFO Diff、计划、执行、验证 |
| `/subjects` | 本地条目 | 作品、季、分集身份和外部 ID |
| `/bindings` | 目录绑定 | 长期作品绑定、标题覆盖和映射 |
| `/parser-rules` | 解析规则 | 规则管理、样本测试、Trace 和超时统计 |
| `/operations` | 操作历史 | 文件变化、校验、失败和回滚记录 |
| `/integrations` | 集成 | Bangumi、TMDB、Emby 配置与健康状态 |
| `/settings` | 系统设置 | 路径、扫描、命名、NFO、校验、Worker、备份 |

审计详情必须展示三方对比：

| 字段 | 文件系统 | NFO | Emby |
|---|---|---|---|
| 标题 | 目录名/文件名 | `title` | Name |

| 外部 ID | 无或目录绑定 | `uniqueid` | ProviderIds |
| 季集 | 文件名 | season/episode | ParentIndexNumber/IndexNumber |

### 4. 具体实施步骤

#### 阶段 0：修订规格和建立测试样本

- 将现有媒体库审计加入产品需求；
- 将最小 NFO 生成提升到 MVP；
- 拆分 `media_category` 和 `content_kind`；
- 增加 Emby 刷新后验证状态；
- 从 NAS 文件名和脱敏 NFO 提取测试 Fixture；
- Fixture 不包含真实视频、密钥或宿主绝对路径。

完成标准：当前发现的主要命名、重复、Sidecar 和类型异常均有测试样本，明确只报告与可执行操作的边界。

#### 阶段 1：工程基线

- 建立后端、前端和 Docker 工程；
- 实现配置加载、结构化日志、request ID 和统一错误响应；
- 初始化 SQLite、Alembic 和数据库备份；
- 建立后端与前端质量检查；
- 实现 health、readiness 和 version。

完成标准：Docker Compose 可启动，空管理台可访问，SQLite 数据库不位于网络共享。

#### 阶段 2：认证和路径配置

- 单管理员登录；
- Session、CSRF、Argon2id；
- 监听目录和媒体库 CRUD；
- 授权根路径校验；
- 可读、可写、设备、文件系统和空间测试；
- 实现登录、目录和媒体库页面。

完成标准：可以安全配置 `/inbox` 和 `/media`，路径越界及符号链接逃逸被拒绝。

#### 阶段 3：只读媒体库审计

- 流式扫描目录；
- 建立文件快照和发现指纹；
- 解析目录、视频、字幕、NFO 和图片关系；
- 检测孤立 Sidecar、重复目录和嵌套异常；
- 读取最小 NFO 字段；
- 持久化 AuditFinding；
- 实现审计列表和详情页。

完成标准：对真实 NAS 扫描时完全不修改文件，并能输出当前库中主要问题类型。

#### 阶段 4：解析器与分组

- 实现纯函数解析流水线；
- 支持标准格式和 NAS 现场格式；

- 实现 Extras 分类；
- 自定义规则及正则超时保护；
- 实现解析 Trace 页面。

完成标准：分辨率和位深不会被当作集号，`Title - 01`、`E421`、`[001]` 和特典样本得到可解释结果。

#### 阶段 5：元数据与身份绑定

- 实现统一 Provider 接口；
- 实现 TMDB 和 Bangumi Adapter；
- 实现搜索、详情、季和分集查询；

- 实现候选评分和人工确认；
- 实现目录绑定；
- 持久化作品、季和分集外部 ID。

完成标准：确认结果可以永久复用，Provider 暂时不可用不会改变已有绑定。

#### 阶段 6：季集映射、命名和 NFO Diff

- 实现绝对集区间映射；

- 生成目标路径和 NFO 操作预览。

本阶段不得修改真实媒体文件。

完成标准：能够为真实问题目录生成完整修复计划，所有冲突在执行前显示，已有 NFO 默认不覆盖。

#### 阶段 7：文件执行和回滚

- 实现 FileSystemPort 和 FakeFileSystem；
- 实现同设备原子移动、copy 和 hardlink；

完成标准：故障注入后不丢文件，目标存在时源和目标均不改变，成功操作可以安全回滚。

#### 阶段 9：Emby 集成与结果验证

- 实现连接测试；

#### 阶段 10：自动扫描与发布硬化

- 定时扫描和文件稳定性检查；
- 自动匹配开关；
- 自动执行继续默认关闭；
- SQLite 定时备份；
- 日志滚动和指标；
- 构建 amd64/arm64 镜像；
- 完成 NAS 权限、SMB/NFS、中断、升级和恢复测试。

完成标准：新文件可以自动进入待确认工作台，并在真实 NAS 上完成只读审计、修复预览、人工执行、回滚和 Emby 验证闭环。

### 5. 第一条纵向交付链路

优先完成以下最小闭环，再扩展到整库和自动执行：

```text
扫描一个现有作品目录
→ 发现问题
→ 确认 Bangumi/TMDB 条目
→ 映射季集
→ 预览重命名和最小 NFO
→ 在隔离测试目录执行
→ 回滚
→ 通知并验证 Emby
```

### 6. 安全边界

- 默认只读审计；
- 默认不自动执行；
- 默认不覆盖；
- 默认不删除孤立文件或重复视频；
- 所有变化必须有计划、快照、操作记录和回滚条件；
- 所有自动化测试使用临时目录，不操作真实 NAS；
- 真实 NAS 首次执行必须限定单个作品目录并人工确认；
- Emby、Bangumi 或 TMDB 失败不得破坏本地文件状态。

## 2026-08-22：第二版界面方案确认与首条纵向链路

### 方案确认

暂定采用 Product Design 第二个方案 “Compact Media Shelf”：

- 首页为番剧海报墙，不使用数据工作台布局；
- 左侧导航严格保留“首页”和“设置”两个入口；

## 2026-08-23：远程分集图缺失时使用视频截图

### 排查结论

- 测试库中《Re：从零开始的异世界生活 第四季 丧失篇》12 个分集均有本地 `*-thumb.jpg`；其余四部共 41 个已解析分集的目录中没有任何本地图片。
- 五部作品的分集 NFO 均没有 `<thumb>`；当前 Bangumi 分集响应也不提供图片字段，因此其他作品显示缺图不是前端匹配遗漏。

### 实现

- 新增独立 `FfmpegEpisodeArtworkGenerator`，分集封面优先级为：Provider 远程图片 → 已有本地 sidecar → ffmpeg 视频截图。
- 截图只随明确确认的 NFO 生成/更新操作执行，只处理用户选中的正片；SP、PV、NCOP/NCED、Menu、Fonts 等保持跳过。
- 输出名固定为 `{视频原始基名}-thumb.jpg`，宽度限制为 960 像素并保持宽高比；默认取视频 25% 位置，短片自动限制在有效时长内。
- 已有 `.jpg/.jpeg/.png/.webp` 的 `-thumb`、`.thumb`、`-poster` 或同名图片时不执行截图；写入使用排他新建，绝不覆盖已有图片。
- 同批最多并发两次 ffmpeg，默认单文件超时 60 秒；缺少可执行文件、超时、解码失败和写入失败均作为结构化 `artwork_warnings` 返回，不影响已完成的 NFO 更新。
- 可通过 `CYMEDIAFLOW_EPISODE_ARTWORK_FALLBACK_ENABLED`、`CYMEDIAFLOW_FFMPEG_PATH`、`CYMEDIAFLOW_FFMPEG_TIMEOUT_SECONDS` 和 `CYMEDIAFLOW_EPISODE_ARTWORK_CAPTURE_PERCENT` 配置。
- 字段保护增加“分集截图封面”锁；锁定后该作品不会自动生成缺失截图。

### 验证

- 后端 35 项测试通过，覆盖 ffmpeg 参数、截图时间点、排他不覆盖、可执行文件缺失、远程图片保留、正片 API 集成和附加内容跳过；Ruff lint/format 通过。
